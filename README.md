# 合流駅ファインダー

2〜8人分の職場・自宅最寄駅を入力すると、公平に集まれる駅を3つの観点から提案するツールです。駅すぱあとAPI(買い切り型)の範囲探索で実際の移動時間を計算します。

## 公開URL

- フロントエンド(GitHub Pages): https://kakeru110.github.io/eki-finder/
- APIプロキシ(Vercel): https://eki-finder.vercel.app/api/multi-range

ジョルダン「乗換案内オープンAPI」の登録フォームで求められる「公開URL」には、GitHub PagesのURLを使用してください(ただしジョルダンの審査は非公開URL用途と判断され却下されたため、現在は駅すぱあとAPIに接続している)。

## システム構成

- `index.html`: フロントエンド(単一HTML)。駅名入力・モード選択・結果表示を行う
- `api/multi-range.js`: Vercelサーバーレス関数。`EKISPERT_API_KEY`をサーバー側の環境変数として保持し、駅すぱあとAPIの「範囲探索(multipleRange)」を中継する。ブラウザにAPIキーを露出させないための唯一の目的
- 入力パターンは「🏠 自宅だけ」(デフォルト、職場欄自体を非表示にし自宅のみ入力。自宅が往復共通の起点でAPI呼び出しを1回に節約)と「🏢 職場と自宅」(職場→集合駅の往路と集合駅→自宅の復路、両方必須)の2つ。切り替えても入力済みの値は保持される
- `合計最短`/`公平重視`は往復合計・往復差で計算し、`最速集合`は到着(往路のみ)で判定する。ランキングは合計値のまま行うが、画面には人数で割った「1人あたり往復○分」を表示する(合計値は人数が増えるほど大きくなり比較しづらいため)
- 自宅だけモードは往路=復路(同じ自宅駅)なので、結果一覧では「往○分+復○分」の内訳を書かず「片道○分」とだけ表示する
- フロントはVercel経由の実データ(往路・復路それぞれ範囲探索)で計算し、失敗時は直線距離ベースの概算値に自動フォールバックする。範囲探索のレスポンスに含まれる`TransferCount`(乗換回数)も`transfersByPerson`として一緒に返し、結果一覧に表示する(概算フォールバック時は乗換回数を表示しない)
- 1回の検索でtotal(往復合計)/spread(往復差)/max(到着時間)を全モード分まとめて計算しているため、検索後にモードタブを切り替えても再フェッチせず並べ替えのみで結果が更新される(`lastSearch`にキャッシュ、人数変更・駅名編集・入力パターン切り替え時は破棄)

## モード

- **合計最短**: 全員の往復移動時間(職場⇄集合駅⇄自宅)の合計が最小になる駅
- **公平重視**: 往復移動時間の差(最大-最小)が最小になる駅
- **最速集合**: 最後の1人が到着するまでの時間(往路のみ)が最小になる駅

終電安心モード(解散予定時刻から終電の余裕を逆算する機能)は、駅すぱあとの買い切り型プランに時刻表情報が含まれず常に概算にしかならないため削除した。

## その他の機能

- 人数は2〜8人の範囲で「＋人を追加」/ 各カードの「✕」で自由に増減できる
- 駅名は候補一覧(約395駅、フロント側の自動補完用)からのサジェスト選択を基本とし、誤字は赤枠+エラーで検索前にブロックする。候補にない駅名でも「未登録駅として使う」を選べば計算に含められる(実データAPIは駅すぱあとの全国データベースを直接検索するため、フロントの候補一覧にない実在の駅名でも問題なく計算できる)。候補一覧はあくまで手作業で用意した部分集合(主要路線+一部支線)なので、マイナーな路線の駅は今後も抜けが見つかり次第追加していく想定

## APIキーの管理

`EKISPERT_API_KEY`はVercelプロジェクトの Settings → Environment Variables にのみ設定し、リポジトリには一切コミットしない。買い切り型プランは5,000リクエストの合計消費制(月次リセットなし、有効期限は未確認)。範囲探索は1回のリクエストで最大5人分を同時に問い合わせられるため、6人以上の場合のみ複数リクエストに分割する(`api/multi-range.js`が自動処理)。「職場と自宅」パターンは往路・復路で2回(5人超はさらに分割)、「自宅だけ」パターンは1回の呼び出しで済む。

## 検討済み・却下した選択肢

- Google Maps系API: 日本の乗換(transit)検索は非対応のため不可
- NAVITIME API(RapidAPI): 無料枠500件のみ、以降月$200〜で個人には割高
- ジョルダン「乗換案内オープンAPI」: 無料だが要審査。「不特定多数がアクセスできるオープンなWebサイト」向け限定のため、個人利用ツールとして却下された
- 駅すぱあとAPI スタンダードプラン: 時刻表情報も使えるが月額サブスクリプションで個人利用には過剰

## 採用: 駅すぱあとAPI 買い切り型プラン

- Amazon.co.jpで「駅すぱあと API for Amazon」として販売(5,000件¥5,500)
- 範囲探索(multipleRange)は利用可能、時刻表情報は利用不可
- 「平均待ち時間ベース」の計算のため、本数の少ない支線(例: JR鶴見線海芝浦支線)では実際の所要時間より過大に出ることがある。実ダイヤに基づく正確な計算にはスタンダードプラン(月額、要問い合わせ)が必要
- **経路探索(`/search/course`)系のエンドポイントはこのキーでは呼び出し不可(実機で`ekispert API error W403`を確認)**。公式の機能比較表では「制限あり」(一部利用可)と表示されていたが、実際には完全にブロックされていた。そのため乗換駅・路線名などの経路詳細を表示する機能は買い切り型プランでは実現できない(2026-08時点)
