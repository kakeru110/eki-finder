# 合流駅ファインダー

2〜8人分の職場・自宅最寄駅を入力すると、公平に集まれる駅を4つの観点から提案するツールです。東京・神奈川・埼玉・千葉の主要私鉄・地下鉄を含む約320駅を候補として登録しています。

## 公開URL

GitHub Pages で公開しています(このリポジトリの `main` ブランチ / ルートを Pages のソースに設定した場合):

```
https://kakeru110.github.io/eki-finder/
```

ジョルダン「乗換案内オープンAPI」の登録フォームで求められる「公開URL」には、上記のURLを使用してください。

> リポジトリ作成直後は GitHub Pages が未有効化の場合があります。Settings → Pages → Source を
> `Deploy from a branch` / `main` / `/(root)` に設定すると数分で上記URLが有効になります。

## 現状

- `index.html`: フロントエンド(単一HTML。フォントのみ Google Fonts の Zen Maru Gothic をCDN読み込み、それ以外は外部依存なし)。4モード切替に対応
  - **合計最短**: 全員の移動時間の合計が最小になる駅
  - **公平重視**: 移動時間の差(最大-最小)が最小になる駅
  - **終電安心**: 解散予定時刻から逆算し、全員が終電に最も余裕を持って間に合う駅
  - **最速集合**: 最後の1人が到着するまでの時間が最小になる駅
- 人数は2〜8人の範囲で「＋人を追加」/ 各カードの「✕」で自由に増減できる
- 駅名は候補一覧(約320駅)からのサジェスト選択を基本とし、`stationMap.has()` による厳密一致チェックに通らない入力(誤字など)は赤枠+エラーで検索前にブロックする。候補に本当にない駅名の場合は、サジェスト内の「未登録駅として使う(概算配置)」を明示的に選ぶことで概算計算に含められる(誤字防止と網羅性のバランスを取る設計)
- `eki-proxy/`: 実際の乗換案内API(駅すぱあと/ジョルダン等)に接続するためのNode.js中継サーバーの雛形。**未接続・要APIキー**
- 現在の所要時間・終電時刻は実データ未接続のため、駅間の直線距離ベースの**概算値**で計算しています(`index.html` 内 `approxTravelMinutes` / `approxLastTrainMinutes`)。候補一覧にない駅(未登録駅として使うを選んだ場合)は駅名のハッシュ値から疑似配置して概算する。

## 検討済み・却下した選択肢

- Google Maps系API: 日本の乗換(transit)検索は非対応のため不可
- NAVITIME API(RapidAPI): 無料枠500件のみ、以降月$200〜で個人には割高

## 検討中

- ジョルダン「乗換案内オープンAPI」: 無料だが要審査・公開URL必須・時刻表情報なし(終電判定に使えない)
- 駅すぱあとAPI買い切りプラン: 5,000件¥5,500、時刻表・終電情報も取得可能な見込み

## 次にやりたいこと

- ジョルダンの審査結果を待ちつつ、駅すぱあとAPI買い切りプランの導入を検討
- 実APIに接続したら `index.html` の概算ロジックを `eki-proxy/` 経由の実データ取得に置き換える
